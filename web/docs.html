League Voice Recorder — Architecture & Technical Internals Guide

Welcome to the definitive architectural and engineering reference for League Voice Recorder & Replay Synchronizer. This document explains the entire codebase end-to-end, featuring deep-dive technical analyses of main.py (Desktop GUI & orchestration) and app/native_audio.py (native Windows WASAPI capture engine).

1 High-Level Architecture Overview

League Voice Recorder solves two mission-critical challenges in professional League of Legends scrimmages and esports reviews:

  • Automated Scrim Audio Recording: Hooks the active match via Riot's Live Client Data API, captures team Discord voice chat directly through native WASAPI process loopback alongside player microphone input, handles mid-game pauses with zero audio drift, and renders a normalized, sample-accurate <GameID>.mp3.
  • Automated Replay Audio Synchronization: Automatically detects launched .rofl replays, matches the official Game ID to the recording, loads the audio into VLC, and continuously locks playback rate (0.5x, 1x, 2x, 4x) and timestamps to the League Replay API.
💡
Zero Memory Injections & Vanguard Compliance
League Voice Recorder interacts strictly with Riot's published localhost HTTP endpoints (port 2999) and Windows Audio Session API (WASAPI). It never touches game memory, hooks game DLLs, or injects foreign code into the League client.

The application operates through two independent, decoupled operational loops: the Live Scrim Audio Recording Pipeline and the Automated Replay Synchronization Engine.

2 Deep Dive: main.py (Desktop GUI & Orchestration Engine)

main.py is the central application entrypoint. Powered by CustomTkinter, it manages the complete desktop application lifecycle, hosts multi-threaded background workers, calculates dynamic multi-monitor geometry, synchronizes the floating HUD overlay, and manages user configuration.

2.1 Headless Stdout & Windows Subsystem Safety

When compiled for production Windows deployment with --windows-console-mode=disable, Windows does not allocate a standard console device (CONOUT$). In pure GUI mode, Python sets sys.stdout and sys.stderr to None.

python 
if sys.platform.startswith("win"):
    if sys.stdout is None:
        sys.stdout = io.StringIO()
    if sys.stderr is None:
        sys.stderr = io.StringIO()
⚠️
Why in-memory StringIO is critical
If any background thread or third-party dependency calls print() or writes to sys.stderr while sys.stdout is None, Python raises AttributeError: 'NoneType' object has no attribute 'write' and terminates silently before displaying the window. Diverting both descriptors to memory buffers eliminates silent startup crashes.

2.2 Startup Centering & Window Geometry Math

To deliver an optimal esports desktop experience across varied resolutions (1080p, 1440p, 4K, 21:9 ultrawide), main.py calculates primary screen bounds and dynamically centers the window:

python 
screen_width = self.winfo_screenwidth()
screen_height = self.winfo_screenheight()
app_width = min(1100, max(920, screen_width - 80))
app_height = min(960, max(750, screen_height - 100))
x = max(0, int((screen_width - app_width) / 2))
y = max(0, int((screen_height - app_height) / 2))
self.geometry(f"{app_width}x{app_height}+{x}+{y}")

2.3 Thread-Safe GUI Communication (self.msg_queue)

Tkinter and CustomTkinter are strictly single-threaded. Any UI modification from a background worker thread causes heap corruption or Tcl_AsyncDelete crashes. main.py implements a robust asynchronous producer-consumer queue pattern:

python 
def _process_queue(self):
    count = 0
    while not self.msg_queue.empty() and count < 40:
        msg = self.msg_queue.get_nowait()
        # Thread-safely dispatches to activity logs, status pills, or health badges
        self._dispatch_message(msg)
        count += 1
    self._queue_timer = self.after(50, self._process_queue)

Background workers (recording watcher, replay synchronizer, auto-updater) emit events via self.msg_queue.put(item) without touching UI widgets directly.

2.4 Dual Engine Watcher Loops

The application provides two self-healing background watcher routines:

  • 🔴 Start Recording Watcher: Runs LeagueRecorder.run_loop() in a dedicated thread. It polls 127.0.0.1:2999/liveclientdata/allgamedata. When a live match begins, it starts WASAPI capture instantly. When the game ends, it automatically saves <GameID>.mp3 and resets the UI button cleanly.
  • ▶ Start Replay Auto-Sync: Runs ReplaySynchronizer.run_loop() in a background thread. It scans for running League of Legends.exe processes executing .rofl replays, parses the Game ID, loads the audio into VLC, and locks audio playback speed to the game replay clock.

2.5 In-Game Floating Overlay Coordination

main.py manages the LeagueOverlay and enforces an Anti-Bleed Game-Exclusive Focus Guard:

  • Foreground Window Check: Queries user32.GetForegroundWindow() to verify that the active window is League of Legends.exe.
  • Auto-Hide on Alt-Tab: When the player Alt-Tabs into Discord, browser, or desktop, the HUD instantly conceals itself. As soon as League regains focus, the HUD reappears.
  • Interactive Click-Through Hit Targets: Even with Windows WS_EX_TRANSPARENT click-through enabled, dedicated transparent hit windows preserve interactivity on the Lock toggle and Replay Volume slider.

3 Deep Dive: app/native_audio.py (Native WASAPI Audio Engine)

app/native_audio.py is the audio engine responsible for recording Discord voice chat and player microphone via Windows Audio Session API (WASAPI) loopback, writing sample-accurate WAV streams, handling match pauses, and rendering normalized MP3 exports.

3.1 PortAudio Process-Wide Singleton Guard

PortAudio enforces strict single-instance lifecycle semantics. Creating concurrent pyaudio.PyAudio() instances across multiple threads causes memory access violations. native_audio.py enforces a thread-safe singleton:

python 
_SHARED_PYAUDIO = None
_SHARED_PYAUDIO_LOCK = threading.Lock()

def get_shared_pyaudio():
    global _SHARED_PYAUDIO
    with _SHARED_PYAUDIO_LOCK:
        if _SHARED_PYAUDIO is None:
            _SHARED_PYAUDIO = pyaudio.PyAudio()
        return _SHARED_PYAUDIO

3.2 Calibrated VU Visualizer Scaling Formula

Human loudness perception is logarithmic rather than linear. native_audio.py implements a calibrated power curve transformation:

python 
_VU_NOISE_THRESHOLD = 0.0002
_INV_VU_RANGE = 1.0 / (1.0 - _VU_NOISE_THRESHOLD)

def scale_vu(peak: float) -> float:
    if peak <= _VU_NOISE_THRESHOLD:
        return 0.0
    val = ((peak - _VU_NOISE_THRESHOLD) * _INV_VU_RANGE) ** 0.42
    return max(0.0, min(1.0, float(val)))

The 0.0002 noise gate suppresses baseline microphone hiss, while the 0.42 power curve expands normal conversational range so audio meters animate fluidly without clipping into the red.

3.3 Discord Audio Capture via WASAPI Process Loopback

Unlike legacy software that requires virtual audio cables (Voicemeeter, VB-Cable), native_audio.py uses native WASAPI Process Loopback via proc-tap:

  • Queries Windows Core Audio Sessions (pycaw) to isolate the active Discord.exe audio output PID.
  • Captures audio directly from the Windows kernel audio session.
  • Receives uncompressed 48,000 Hz, 16-bit stereo PCM audio with zero interference from in-game sounds or browser music.

3.4 Discord Mute/Deafen Silence Injection

When a player mutes their microphone on Discord, Discord stops transmitting audio packets. If a recorder stops writing to disk, the audio stream becomes shorter than the game clock, permanently desynchronizing voice comms from gameplay!

python 
# When Discord mute state is active:
silence_bytes = b"\x00" * int(elapsed * 48000 * frame_size)
self.discord_writer.write_frames(silence_bytes)

By injecting synchronized zero bytes during mute periods, the timeline stays locked to the League match clock frame-by-frame.

3.5 Zero-Drift WAV Truncation Math (truncate_to_game_time)

When an in-game pause occurs in a scrim, Riot's Live Client Data API takes 400ms–450ms of polling intervals to verify that gameTime is frozen. During those 450ms, audio was already written into the WAV file. TimelineWavWriter.truncate_to_game_time(pause_game_time) permanently eliminates pause lag with sample-accurate in-place file truncation:

python 
target_frame = int(round(target_game_time * self.sample_rate))
target_byte_pos = 44 + (target_frame * self.frame_size)
self._file.seek(target_byte_pos)
self._file.truncate()
self.current_frame = target_frame
self._update_wav_header()
⭐
Zero Cumulative Pause Drift
Seeking back to 44 + (target_frame * frame_size) and truncating slices out the 450ms detection delay. When the game unpauses, recording continues sequentially with zero cumulative drift.

3.6 Sample-Accurate FFmpeg Alignment Pipeline

When match recording ends, native_audio.py exports the final audio stream using FFmpeg:

bash 
ffmpeg -y -i disc.wav -i mic.wav \
  -filter_complex "[0:a]volume=1.0[disc];[1:a]volume=1.3[mic];[disc][mic]amix=inputs=2:duration=longest" \
  -c:a libmp3lame -b:a 192k "<GameID>.mp3"

Security & Vanguard Compliance

League Voice Recorder is built to adhere strictly to Riot Games third-party application policies:

  • Zero memory reading or writing; zero DLL injection; zero game process modification.
  • Queries only official, unauthenticated localhost endpoints published by Riot.
  • Audio captured entirely through standard Windows WASAPI process loopback.
  • All build binaries and setup packages are continuously scanned against 70+ antivirus engines via VirusTotal API v3.
